## Decisions already made

- **Kind** by extension, any letter case. **Depth** is the number of folders between `Mods` and the file.
  `Mods/Resource.cfg` is not listed in `files`.
- **Package reader.** Read the 96-byte header and the index only, through `openForRead`. Never the whole file.
  - Shorter than 96 bytes: `broken / too-short`. Magic not `DBPF`: `broken / bad-magic`.
  - Version 2.1: Sims 4. 1.1 is `sims2`, 2.0 is `sims3`, 3.0 is `simcity`, anything else `unknown`: `wrong-game`.
  - Index offset: the 4 bytes at 40 when not zero, else the 8 bytes at 64. `broken / bad-index` when
    offset + size passes the end of the file, when the size is not `4 + 4k + count × (32 − 4k)` (k = constant flags
    set), or when the index is over 64 MB. A count of 0 is `ok` with no keys.
  - Keys print as `0x` + uppercase hex: 8, 8 and 16 digits. Deleted entries (`0xFFE0`) are listed like any other.
  - A file that cannot be opened is `unreadable`, never `broken`.
- **Script reader.** Read the `.ts4script` (over 64 MB: `broken`), then `fflate`'s `unzipSync` with a `filter` that
  records each name and returns `false`, so nothing is unpacked or run.
- **Hash.** Hash a file (`sha256File`) only when another file has the same byte count. Otherwise `not-needed`.
- **`Resource.cfg`.** Depth is the largest number of `*/` parts in a `PackedFile` line. No file: `missing`.
- **CurseForge.** Read `AddonGameInstance.json` (16 MB at most) in the shape the fixture generator writes
  (`scripts/fixtures/templates.ts`): take the instance with `gameID` 78062. A file belongs to an addon when its
  `RelPath` equals `fileNameOnDisk` (with `\` turned into `/`), or else when its base name equals the base name of
  `fileNameOnDisk` or a module name; any letter case. Any surprise in the JSON gives `unreadable` with a
  reason; it never throws. **G1 settles the real shape.**
- **Groups**, in this order, each file in exactly one: files matched to a CurseForge addon (`cf:<addonId>`); then by
  top-level folder (`dir:<name>`); then one group per loose file (`file:<relPath>`). Ids are lowercased.
- **Walk.** Follow a linked folder once (remember real paths, as PR 3 does) and never leave `Mods`. A folder or file
  that cannot be read goes in `skipped`. `Mods` missing: `modsDirState: 'missing'` and empty lists.
- **Speed.** At most 8 files open at once. Send `progress` (`counting`, then `mods` with done and total) at most once
  every 100 ms.

## Tests to write first

- `dbpf.test.ts`: every package in the `broken-packages` fixture gives the status and, for the good ones, the exact
  keys its spec names (three constant-flag layouts). A 96-byte file with count 0 is `ok`.
- `scripts.test.ts`: entries of the `exceptions` scripts match the spec; a cut zip is `broken`.
- `inventory.test.ts`, one block per fixture: `clean`, `nested-scripts` (depths, French folder, 3-level
  `Resource.cfg`), `duplicates` (same-size files are hashed and equal; others `not-needed`), `broken-packages`
  (archives are `archive`), `exceptions` (CurseForge found, `cf:` groups), `big` (5,000 packages, 300 scripts).
- Every file is in exactly one group, and `groupId` matches.
- **Read-only proof:** snapshot a fixture tree (every file, folder, date and hash) before and after
  `buildInventory`, as `src/main/locate/read-only.test.ts` does. It must be identical.
- A `Mods` folder holding a link that loops ends, and lists each file once.
