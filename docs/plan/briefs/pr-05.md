# Brief: PR 5, crash and exception log readers

**Goal.** Turn every log the game and its diagnostic mods leave behind into `LogReport`s. A reader never throws,
whatever the file holds, and never names a mod from a hard-crash log.

- **Base:** `wells/contracts`. **Branch:** `wells/pr-05-logs`. **Title:** `feat(logs): read crash and exception logs`.
- **You own:** `src/main/logs/**`, `scripts/fixtures/specs/pr-05-*.json`. Nothing else.
  [`ownership.md`](../ownership.md) wins over `plan.md`.
- **Read first:** [`contracts.md`](../contracts.md) sections 1, 2 ("Logs") and 4;
  `docs/research/fable-files-logs-safety.md` section 3; `scripts/fixtures/templates.ts` (the exact fixture formats).
- **You implement:** `parseGameLog`, `parseBetterExceptions`, `parseMccc`, `readLogs`, and `src/main/logs/cli.ts`
  (`npm run logs -- <fixture root>`).
- **You may call:** `src/main/fs-read.ts`, and PR 3's `locate` (in `cli.ts` and tests only). No XML or HTML package.

## Decisions already made

- **No XML parser.** The files are flat, and a crash can cut one off. Find each report by scanning for `<report>`
  and `</report>` with `indexOf`, then read each field with one small pattern per tag. A last report with no closing
  tag is still read, with `completeness: 'cut-off'`. A missing field is `null`.
- **Decode** `&#13;&#10;` and other numeric references (decimal and hex), `&lt;`, `&gt;`, `&amp;`, `&quot;`, `&apos;`.
- **Kind.** `<type>crash</type>` is `crash`. Otherwise a file name starting `lastUIException` is `uiException`, and
  the rest are `exception`.
- **Group** the reports of one file by `categoryid`: one `LogReport` per category, `count` = how many, fields and
  frames from the first one.
- **Python frames:** lines matching `File "<path>", line <n>`. A frame is `game` when its path, lowercased with `/`,
  starts with `t:/ingame/`; every other frame is `mod`. `modHints` holds each distinct mod path, lowercased, `/`,
  without `.py`, `.pyc` or `.pyo`.
- **UI exceptions:** `at <name>()` lines become frames with `line: null` and `origin: 'game'`. They never give a
  `modHint` (a UI mod cannot be told from the game here).
- **Crash logs:** time and version only. `frames` and `modHints` are always empty.
- **`gameVersion`:** the first `d.d.d.d` in `<buildsignature>`. **`createdLocal`:** the `<createtime>` text, as is.
- **Better Exceptions:** take the text inside `<div id="beRawLEData" ...>`, undo the HTML escaping, and run
  `parseGameLog` on it with kind `betterExceptions`. No such block: return `[]`. Do not read "Possible Cause"; the
  research calls it misleading.
- **MCCC:** drop the tags, undo the escaping, read `File "..."` lines as above. One report, `categoryId: null`,
  `gameVersion` from a "Game Version:" line when there is one. **G1 settles the real layout.**
- **`readLogs`** looks, any letter case, at the top of the Sims folder for `lastException*.txt`,
  `lastUIException*.txt`, `lastCrash*.txt` and `BE-ExceptionReport*.html`, and for `mc_lastexception.html` under
  `Mods` down to two folders deep. Result is newest first by `fileModifiedAt`.
- **Limits.** Read at most the first 8 MB of a file (`openForRead`); a longer file is `cut-off`. A file that cannot
  be read is left out. Keep 60 frames and 300 characters of `message`.
- No pattern may backtrack badly: an 8 MB file of `<` characters must parse in under 2 seconds.

## Tests to write first

- One test per format, built from the `exceptions` fixture (`scripts/fixtures/specs/exceptions.json` names what each
  file holds):
  - `lastException_63887256771.txt`: one report, `count` 2, `categoryId` `tunable.py:2138`, all frames `game`,
    no `modHints`.
  - `lastException_63887259912.txt`: `modHints` is
    `['c:/users/modauthor/projects/wicked_wardrobe/outfit_picker']`.
  - `lastException_63887260105.txt` (cut off): still gives `categoryId` `zone.py:890` and is `cut-off`.
  - `lastUIException.txt`: kind `uiException`, frames present, no `modHints`.
  - `lastCrash.txt`: kind `crash`, version `1.129.39.1030`, no frames, no `modHints`.
  - `BE-ExceptionReport.html` and `MCCC/mc_lastexception.html`: kinds, version, frames.
- Entities: `&#13;&#10;` splits lines; `&lt;module&gt;` reads as `<module>`.
- Never throws: an empty file, 1 MB of random bytes, 8 MB of `<`, a file that is only `<report>`.
- `readLogs` on `exceptions` returns every file above, newest first; on `clean` it returns `[]`.
- **Read-only proof:** a tree snapshot before and after `readLogs` is identical.
