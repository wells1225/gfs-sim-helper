# Brief: PR 14, share saves between Lila's PC and Tyler's PC

**Goal.** She picks a save and clicks **Send to Tyler's PC**. On his PC the app says it is ready, he clicks **Get
it**, and the newer copy takes the place of his older copy of that same save. The copy it replaced is kept in **Old
saves** and can be put back. It works the same way back. The save carries the list of mods and packs it was played
with, and the other PC shows what is missing and where to get it.

## The design in one page

- **Transport.** A Google Drive folder named exactly `Sims Helper Share`, owned by Tyler and shared only with her
  account. Google Drive for desktop syncs it on both PCs. Our app reads and writes that folder as plain files. It
  never signs in to Google, holds no Google token and calls no Google API.
- **What travels.** One file: the slot's `Slot_XXXXXXXX.save`. The game's own `.save.ver0` to `.ver4` files never
  travel and are never touched on either PC. Tray never travels.
- **Which save is which.** Each shared save gets a `shareId` when it is first sent. Each PC keeps its own link:
  `shareId` to a local slot name, plus the SHA-256 that slot had at the last handoff. Slot numbers are local and
  never leave the PC. The manifest never names a slot or a path.
- **A replace is bound to a hash, not to a slot number.** The local file is replaced only when it still has the
  hash from the last handoff and the incoming copy grew from that same copy. Anything else replaces nothing.
- **The write into `saves/` is two moves.** The old copy moves out to Old saves, then the checked incoming copy
  moves in. Nothing in `saves/` is ever overwritten or deleted, so the gate's "never overwrite" rule still holds.
- **Sync is trusted only after a check.** The incoming file is copied from the Drive folder to the app's own
  folder, and that copy is checked against the manifest (size and SHA-256). Only the checked copy can reach `saves/`.
- **"It arrived" comes from the other PC.** Our app cannot see Drive's upload. The receiving PC writes a small
  `got` file, and the sender then shows "Tyler's PC got it".

## The Drive folder (every file is written once, by one PC)

```
Sims Helper Share/
  pc-lila.json   pc-tyler.json            hello files; each PC replaces only its own
  s-<id>/                                 one folder per shared save (shareId)
    000007-lila/                          one folder per handoff: <seq, 6 digits>-<sender>
      shared.save                         the save's bytes
      manifest.json                       written last: a folder without it is not finished
      got-tyler.json                      written by the PC that got it
```

`manifest.json` (UTF-8, 256 KB at most). No absolute path, no slot name, no Windows user name, no Google address:

```json
{ "format": 1, "app": "sims-helper", "appVersion": "0.4.0", "shareId": "s-20261124-193045-k3f9",
  "name": "The Wells legacy", "seq": 7, "from": "lila", "sentAt": "2026-11-24T19:30:45.000Z",
  "save": { "bytes": 38123456, "sha256": "<64 hex>", "savedAt": "2026-11-24T19:12:03.000Z" },
  "lineage": [{ "seq": 6, "sha256": "<64 hex>" }, { "seq": 5, "sha256": "<64 hex>" }],
  "game": { "version": "1.110.265.1030", "packs": ["EP01", "GP02"], "modsOn": true, "scriptModsOn": true },
  "mods": {
    "curseForge": [{ "addonId": 663350, "fileId": 9396860, "name": "MC Command Center", "hasScript": true,
                     "fileDate": "2026-11-02T10:00:00.000Z" }],
    "other": [{ "label": "wonderfulwhims", "files": ["WonderfulWhims.ts4script"], "hasScript": true,
                "creator": null, "title": null, "link": "https://example.com/the-page" }] } }
```

- `lineage`: the copies this one grew from, newest first, 20 at most. `seq` orders handoffs; the hashes decide.
- `mods` is her Mods folder at the moment of sending: the `cf:` groups (ids from `AddonGameInstance.json`) and the
  folder and loose groups (`label`, file names without folders, 20 at most). `creator` and `title` are `null` in
  this PR: PR 4's inventory reads neither from a package. Never guess them from a file name.
- `link` is an address the sender typed for a manual mod, or `null`.
- `pc-<role>.json`: `{ format, role, pcId, appVersion, at, heard: { pcId, at } | null }`. `pcId` is a random id
  made on first use. `got-<role>.json`: `{ format, by, at, sha256 }`.
- The reader ignores every name that is not one of these patterns (Drive and the gate's temp-then-rename both
  leave stray names in a synced folder).

## Decisions already made: unit B, the gate (Fable)

Two new zones. Everything else in `contracts.md`, section 5, stays as it is. `Tray/` stays forbidden with no exception.

| Zone | Paths | Before any op runs |
|---|---|---|
| save slot | `<folderPath>/saves/Slot_<8 hex digits>.save`, directly in `saves`, nothing else | game `not-running` and backup `verified` |
| share | `<shareRoot>` and the exact names in "The Drive folder" under it | `folderPath` given |

- **These rules are about ops that move a slot file.** Reading stays as it is: any file in `saves/` is still a
  plain `copy` source for any reason, many per request, with no backup asked. PR 9's backup and this PR's Send
  both copy out of `saves/`.
- **Save slot: `move` only.** `mkdir`, `copy` into, `write` and `remove` are refused there, as today, with
  `saves-or-tray`. So is every other name under `saves/`: `.ver0` to `.ver4`, `scratch/`, a subfolder, a slot name
  with a trailing dot or space, a data stream.
- **The other side of the move** must be under `paths.oldSavesDir` or `<paths.shareDir>/incoming/`. Never Mods,
  never another path in `saves/` (no slot renames), never anywhere else in app data.
- **One slot per request.** A request may move one save-slot path, in at most two ops, and then the move out comes
  before the move in. The move in never overwrites: a file already at the slot fails the op.
- **Reason.** A request that moves a save slot must have `reason: 'share-save'`, and a `share-save` request may
  write nothing in Mods, caches or `Options.ini`. The reason is a tripwire against a caller's mistake, not a lock.
- **Share root.** `deps.shareRoot()` is asked fresh for each request; `null` or a throw refuses. The folder's own
  name must be `Sims Helper Share`. Refuse a root inside (or holding) the Sims folder or `dataDir`, under a
  OneDrive root, with a `saves` or `Tray` part, or whose real path is not the path given (`link-escape`).
- **Share ops.** `mkdir`: the root, `s-<id>`, `<seq>-<role>`. `copy` into `shared.save` only from
  `<shareDir>/outgoing/`. `write` with `create`: `manifest.json`, `got-<role>.json`. `write` with `replace`:
  `pc-<role>.json`. `remove`: a whole `<seq>-<role>` folder. A `copy` out of the share zone may land only under
  `<shareDir>/incoming/`. No `move` in or out.
- **Send reads a save with the game closed.** A request with `reason: 'share'` whose `copy` reads from `saves/`
  needs the game `not-running`, and no backup: nothing in the Sims folder changes. This is the only share rule
  that asks about the game; a backup's copy (`reason: 'backup'`) is not affected.
- **Lint** (`gate-lint.test.ts`): the text `share-save` and the actions `share-receive` and `share-restore` appear
  in no non-test file except `gate.ts`, `safety/actions.ts`, `share/receive.ts` and the two contract files that
  declare them (`shared/model.ts`, `main/ports.ts`).

## Decisions already made: unit C, decide and receive (Fable)

- **`decide.ts` is pure.** `checkManifest(raw, folderName)`: exact types, `format` 1 (a higher one is
  `needs-newer-app`), `shareId` and both hashes by pattern, `seq` and `from` equal to the folder name, bytes from 1
  to 2 GiB, ids positive whole numbers, every string capped and stripped of control characters, lists capped (5,000
  mods, 200 packs, 20 lineage entries), unknown keys dropped. A `link` that `safeWebLink` refuses becomes `null`.
- **`decideReceive(link, local, incoming)`** gives one verdict:

| Verdict | When | What happens |
|---|---|---|
| `mine` | `incoming.from` is this PC | nothing |
| `add` | no link for this `shareId`, or the linked slot file is gone | the copy goes into a free slot; nothing is replaced |
| `have-it` | the local file already has the incoming hash | nothing moves; the link takes the incoming handoff |
| `old` | `incoming.seq` is not above the link's | nothing |
| `replace` | the local file still has the link's hash **and** that hash is in `incoming.lineage` | the two moves |
| `ask` | everything else: she played here since the last handoff, or the copy did not grow from ours | replace nothing; add the copy in a free slot; ask her which one to keep sharing |

- **`pickFreeSlot(names)`**: one above the highest slot number in `saves/`, counting `.save` and `.ver` names.
  Never `Slot_00000001`. None free: refuse.
- **`decideSend`**: `get-first` when the folder holds a handoff from the other PC that is not in our lineage;
  `nothing-new` when the file still has the link's hash; `answer-first` while an `ask` is open; else `send` with
  `seq` one above the highest seen, and the new lineage.
- **`answerAsk(link, incoming, keep)`** is what `share:keep` runs, and it moves no file. Until she answers, Send
  is `answer-first`.
  - `theirs`: the link now points at the slot the copy was added to, with the incoming hash, `seq` and lineage.
    Her own copy stays in its slot as an ordinary save that is no longer shared.
  - `mine`: the link keeps its slot. Its `seq` becomes the incoming `seq`, and the incoming handoff is added to
    its lineage. Her next Send is then one above it and names it as a copy it replaces, so the other PC, whose
    file still has that hash, gets a `replace`. The added copy stays in its slot as an ordinary save.
- **`links.ts`.** `safeWebLink(text)`: `https` only, no user or password, no port, a host name with a dot (no IP
  address), 300 characters at most; returns `{ url, host }` or `null`. `curseForgePage(addonId)` builds
  `https://www.curseforge.com/projects/<addonId>` from a number. `placeOf(host)`: `usual` for `curseforge.com`,
  `patreon.com`, `modthesims.info` and their subdomains, else `not-usual`.
- **`receive.ts` is the only code that plans a write into `saves/`.** `receiveSave(deps, { shareId, seq,
  olderGame })` trusts nothing handed to it and looks each fact up itself, in this order:
  1. A 50/50 session is running, or the game is not `not-running`: refused.
  2. `share.json` cannot be read: `state-damaged`.
  3. Read `manifest.json` (size checked first) and run `checkManifest`.
  4. Look at `shared.save` twice, 2 s apart: the size must equal the manifest's and not change. Else `arriving`.
  5. `copy` it to `<shareDir>/incoming/<entryId>/shared.save` through the gate. Hash that copy. A wrong size or
     hash removes the copy: `arriving` in the first 30 minutes after `sentAt`, `damaged` after.
  6. Hash the linked local slot and run `decideReceive`.
  7. The sender's game is newer than this PC's (first three parts of the version): `game-older`, unless
     `olderGame` is `'go'`.
  8. `replace`, `add` or `ask`: build the plan and call `safety.runAction`. `replace` is two `move` steps, each
     with `expect` (size and hash): the slot to `<oldSavesDir>/<shareId>/<entryId>/<slot name>`, then the checked
     copy to the slot. `add` and `ask` are the one move in.
  9. On `done`: save the link (slot, hash, lineage, and the link as it was before, for Undo), record the old copy,
     close the Undo of this share's earlier entries, prune Old saves, write `got-<role>.json`.
- **`restoreOldSave(deps, oldId)`** is the same swap: the current file to Old saves, the chosen old copy to the
  slot. After it the file no longer has the link's hash, so the next incoming copy asks instead of replacing.
- **Backup (Tyler, 2026-11-24: Old saves is enough).** A save swap makes no whole-folder safety copy and never
  refuses for disk space on that account. The replaced save's protection is the move to Old saves, checked by hash;
  PR 9's "verified" looks only at `Mods` and does not gate this swap. `runAction` still journals the swap.
- **A crash between the two moves** leaves an `in-progress` journal entry; `safety.recover()` puts the old copy
  back. A crash after the moves and before the link is saved heals itself: the next look gives `have-it`.

## Decisions already made: unit E, the journal (Opus, from this brief)

Four small changes in PR 9's code. Write each failing test first.

- A planned `move` may carry `expect: { bytes, sha256 }`. `runAction` hashes the source before it writes the
  journal entry and refuses `out-of-date` / `file-changed` when it differs. Nothing has changed at that point.
- `runAction` and `undo` send `reason: 'share-save'` when the entry's action is `share-receive` or
  `share-restore`, and `'fix'` or `'undo'` as today otherwise.
- `closeUndo(entryId)`: sets `undo: 'cannot-undo'` on a `done` entry and changes nothing else. A second call, or an
  unknown id, does nothing.
- `undo` of a `share-receive` or `share-restore` entry checks every step before it moves anything. When a file no
  longer has its recorded hash (she played the save since), it refuses `out-of-date` / `file-changed`, sets
  `cannot-undo`, and leaves the status `done`: never `needs-attention`. Old saves is then her way back.

## Decisions already made: unit F, folder, state and send (Opus)

- **`state.ts`.** `<stateDir>/share.json`, written through the gate (`reason: 'state'`): role, `pcId`, share root,
  `keepOld` (5; 2 to 10), `keepInDrive` (3; 1 to 10), the links, the Old saves list, the typed mod links. A file
  that does not parse is `damaged`: every changing call refuses and nothing is rewritten over it. On each
  `share:get`, a link whose last receive entry is `undone` in the journal goes back to the link saved before it.
  And when a linked slot's size or date changed and its hash is no longer the link's, `safety.closeUndo` is called
  for that link's last receive entry, so History stops offering an Undo that would lose her play.
- **`drive.ts`.** `findShareRoot()`: look for a folder named `Sims Helper Share`, two levels deep, under
  `<letter>:\My Drive` for each drive letter, under `<letter>:\.shortcut-targets-by-id\*`, and under `My Drive`
  and `Google Drive` in the user's home folder. One hit is taken; none or several means she picks. The picked path
  comes from main's own folder dialog (`ctx.pickFolder`), is resolved with `realpath`, and is stored in main. The
  renderer never sees or sends a path: it gets `folderLabel`, redacted.
- **The sync check.** `share:check` writes this PC's `pc-<role>.json` and reads the other one. `waiting` until the
  other file is there; `same-role` when it names our role with another `pcId`; `connected` after. `otherHeardUs`
  is true when the other file's `heard.pcId` is ours: that proves the upload from this PC.
- **`send.ts`,** in this order: `decideSend`; the game must be `not-running` and no 50/50 session running (mods
  set aside would make the list wrong); hash the slot file; `copy` it to
  `<shareDir>/outgoing/<shareId>-<seq>/shared.save`; hash the copy and the source again, all three equal; `mkdir`
  the handoff folder; `copy` into it; read the Drive copy back and compare the hash; write `manifest.json` last;
  save the link; remove the outgoing copy; remove this PC's own handoff folders of that share beyond `keepInDrive`.
  A failure part way removes what it wrote and changes no link.
- **Old saves.** After a replace, the copies of that share beyond `keepOld` are removed, oldest first, and
  `safety.closeUndo` is called for each one's entry. Incoming copies of entries that are `undone` or closed are
  removed at start.
- **Handlers** check every request's shape. A `slotId` must be a slot name in the folder right now; a `shareId`,
  `seq`, `oldId`, `linkId` or mod `key` must be one main listed itself. `share:open-link` opens only addresses in
  main's own table: the Drive download page, `curseForgePage(id)`, a sender link and an AI find, each through
  `safeWebLink`. `share:send` and `share:receive` send `progress` events.
