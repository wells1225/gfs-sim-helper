# Brief: PR 16, patch day guard and the Play button

**Goal.** She opens Sims through the app's **Play** button. If the game updated since last time, the app stops her
before the game starts, makes a save copy, and offers to set aside the script mods older than the update. Later a
**Waiting on** list shows which of those mods have an update, so she can turn each back on.

## Round 7 additions (landed by the round-7 PR, not by you)

```ts
// model.ts
export type GameVersionWatch = { current: string | null; lastSeen: string | null; changed: boolean;
  seenAt: IsoTime | null } // changed: both known and different
export type WaitingOnMod = { groupId: string; label: string; entryId: string; setAsideAt: IsoTime;
  state: 'waiting' | 'updated' | 'back-in-mods' | 'not-curseforge'; updatedAt: IsoTime | null }
export type PlayAnswer = { kind: 'started' } | { kind: 'stopped'; why: 'game-updated'; watch: GameVersionWatch }
  | { kind: 'refused'; why: 'already-running' | 'no-install' | 'error' }
// ipc.ts
'patchguard:watch': { req: void; res: GameVersionWatch }
'patchguard:seen': { req: void; res: GameVersionWatch }        // she said "I've dealt with it": lastSeen := current
'patchguard:play': { req: { ignoreUpdate: boolean }; res: PlayAnswer }
'patchguard:waiting': { req: void; res: WaitingOnMod[] }
```
`patchguard:seen` and `patchguard:play` are in `CHANGING_CHANNELS`. `index.ts` injects
`openGame(exePath): Promise<void>` (Electron `shell.openPath`) into `createContext`, the same way it injects
`openExternal`; only `index.ts` imports `electron` for it.

## Decisions already made

- **Last seen version.** `state/game-version.json`: `{ format: 1, version, seenAt }`, written through the gate
  (reason `state`). The current version is PR 3's `findGameInstall(...).version`. On the very first run there is
  nothing to compare: store the current version and say nothing.
- **The banner.** On app start, `patchguard:watch`; if `changed`, a calm banner on every screen: "The Sims 4 updated
  (1.129 → 1.130). Script mods often break after an update." Buttons: **Get ready** (opens #27's patch day screen)
  and **Not now**. `lastSeen` moves to `current` only on **I'm ready, let's play** at the end of that screen, never on
  start.
- **Play.** `patchguard:play`: if the game is already running, `already-running`. If the version changed and
  `ignoreUpdate` is false, answer `stopped` and show the patch day screen. Otherwise call `openGame` with
  `<install>/Game/Bin/TS4_x64.exe` (never `TS4_DX9_x64.exe`) and answer `started`. Play never changes a file. If
  `gameState()` is not `running` 60 seconds later, the screen says: "If the game didn't open, open the EA app, then
  press Play again." (Players report the exe starts the game "most of the time"; research section 3.)
- **Get ready (on #27's screen).** Step 1: **Save a copy of my saves** (`savecopies:make` with `game-updated`; done
  automatically the first time the screen opens after an update, and shown as done). Step 2: the existing **Set aside
  all script mods**. Step 3: **I'm ready, let's play** (`patchguard:seen`, then `patchguard:play`).
- **Waiting on.** Every group from `groups:disabled` with `origin: 'fix'` whose entry is newer than the version
  change. For a `cf:<addonId>` group, read `AddonGameInstance.json` now: if that addon's `fileDate` is newer than
  `setAsideAt`, `updated`. If the addon's file is already back in Mods (CurseForge put a new one there), `back-in-mods`. How CurseForge
  behaves when a managed file was moved out is unverified (research section 4); the live check settles it.
  A group with no CurseForge id is `not-curseforge`: "Check the creator's page."
- **Turning one back on.** `updated`: **Turn it back on** is the existing `enable-group` undo. `back-in-mods`: the new
  version is already in Mods, so the old copy in holding is no longer needed; the button is **Clear the old copy**,
  a `remove` of that entry's holding folder in app data, after a confirmation. Never put an old copy back beside a
  new one.
- **No network.** No CurseForge API (plan decision: not in v1). Only the local file CurseForge writes.

## Tests to write first

- Watch: first run stores and reports `changed: false`; a new version gives `changed: true`; unreadable state counts
  as first run; `seen` makes `changed` false.
- Play: running game refuses; changed version stops unless `ignoreUpdate`; otherwise `openGame` gets the exe path.
- Waiting: four groups, one per state, from a fixture `AddonGameInstance.json` and a fake journal.
