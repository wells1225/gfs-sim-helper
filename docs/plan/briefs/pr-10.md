## Decisions already made

- **`planFix` is pure.** It returns steps, or a refusal when a file or group is not in the scan (`out-of-date`).
  - `turn-mods-on`: one `edit` of `Options.ini` setting `modsdisabled=0` and `scriptmodsenabled=1` in `[options]`.
    Every other byte and the line endings stay. A missing key is added to that section.
  - `move-script-up`: `Mods/a/b/c/x.ts4script` moves to `Mods/a/x.ts4script` (its top folder, depth 1). A name
    already there: refuse with `file-changed`.
  - `set-aside-files`: each file moves to `<holdingDir>/<entryId>/Mods/<relPath>`.
  - `clear-caches`: one `remove-cache` step per `CACHE_NAMES` entry that exists. This is the only fix with no undo.
  - `disable-group`: `DISABLE.plan(group, ...)`, one journal entry per group (`contracts.md`, section 6).
  - `enable-group`: no plan. Find the group's `done` disable entry and call `safety.undo`.
- **`applyFix`:** `planFix`, then `safety.runAction` with the progress callback. You do not make backups:
  `safety.runAction` and `safety.undo` make one first when needed, and a refused backup comes back as
  `{ why: 'backup' }`.
- **`setAside`** runs one action per group, in order, and stops at the first that is not `done`. **`putBack`** undoes the open disable entries of those groups. **`disabledGroups`** lists groups whose
  disable entry is `done`.
- **Handlers.** `fix:apply` turns a `FixCall` into a `FixRequest` from `ctx.session.scan`: the finding and the fix
  must be in that scan, or the group must be. It refuses with `fifty-fifty-running` when
  `<stateDir>/fiftyfifty.json` holds a phase other than `found` or `stopped`. The first `journal:list` call runs
  `safety.recover()`.
- **Buttons.** "Turn mods back on", "Move it up a folder", "Set aside", "Clear temporary cache". Never "Delete" or
  "Quarantine". No "Are you sure?" box: act on the click, then show the result on the card and a toast with
  **Undo**. While a backup runs, the card says "Making a safety copy first…" with progress.
- **After a fix:** the card shows a check mark and "Check again", which calls `setScan(null)` and goes to `check-up`.
- **Refusals in plain words,** one message per `FixRefusal` case, kept in `src/renderer/fixes/words.ts`. For
  example `game-running`: "The Sims 4 is still open. Save and close the game, then try again." with a
  **Try again** button. `game-state-unknown` says we could not tell whether the game is open, and changes nothing.
- **Your mods:** the groups of the session scan plus the disabled ones, a search box, a switch per group, the
  script-mod groups marked. **History:** newest first, plain summaries ("Set aside 3 zip files from Mods"), an
  **Undo** button that becomes a quiet "Undone" label, "can't be undone" for cache clears, and all entries of one
  50/50 session folded into one row.

## Tests to write first

- `planFix`, one test per fix kind, including the refusals. The `Options.ini` edit keeps CRLF and unknown keys.
- `applyFix` with a fake `Safety`: a backup refusal and a gate refusal each come back unchanged, and progress from
  the backup reaches the callback.
- `setAside` stops at the first failure and reports the entries so far. `putBack` undoes exactly those groups.
- Handlers: an unknown finding id, a fix the finding does not offer, and an unknown group are each refused; a
  running 50/50 session refuses `fix:apply`.
- Components with `fakeApi`: each button label, the backup progress, the toast Undo, every refusal message, History
  rows, the folded 50/50 row, the mods switch.
