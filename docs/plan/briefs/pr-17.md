## The shared folder (one Google Drive folder, synced by Google Drive for desktop)

```
Sims Helper Mods/                 owned by Tyler, shared with her account only, as Editor
  requests/r-<yyyymmdd-hhmmss>-<4 random a-z0-9>.json   written once by her PC, never changed
  from-tyler/<request id>/        written by the relay or Tyler's PC
    files/<the mod's files>       .package and .ts4script only
    ready.json                    written last: a folder without it is not finished
```
- `r-*.json`: `{ format: 1, id, at, text, game: { version, packs }, mods: [group labels] }`. `text` is 2,000
  characters at most. No path, no Windows user name, no email address.
- `ready.json`: `{ format: 1, requestId, title, note, files: [{ name, bytes, sha256 }], hasScript }`. `note` is
  Tyler's plain words for her ("Sims now react to new outfits. Turn on script mods in Game Options."). It names any mod hers must also have, such as XML Injector.

## Round 7 additions (landed by the round-7 PR, not by you)

```ts
// model.ts
export type ModRequest = { id: string; at: IsoTime; text: string;
  status: 'sent' | 'ready' | 'installed' | 'broken'; delivery: ModDelivery | null }
export type ModDelivery = { title: string; note: string; files: { name: string; bytes: number }[]; hasScript: boolean }
export type ModFolderState = { kind: 'set'; path: string } | { kind: 'not-set' }
  | { kind: 'missing' | 'wrong-name' | 'in-sims-folder'; path: string }
// ipc.ts
'requests:folder': { req: void; res: ModFolderState }
'requests:pick-folder': { req: void; res: ModFolderState }   // opens the folder picker
'requests:send': { req: { text: string }; res: { kind: 'sent'; request: ModRequest } | { kind: 'refused'; why: 'no-folder' | 'too-long' | 'empty' | 'error' } }
'requests:list': { req: void; res: ModRequest[] }
'requests:install': { req: { requestId: string }; res: FixOutcome }
```
`ActionKind` gains `'install-mod'`. `GateDeps` gains `modFolderRoot(): string | null`, read from
`state/mod-folder.json`. The last three channels and `pick-folder` are in `CHANGING_CHANNELS`.

**Gate, new zone `mod-folder`** (Opus through OpenCode writes it in round 7, tests first):
- The root is `modFolderRoot()`, only when its base name is exactly `Sims Helper Mods`, it is not inside a Sims folder,
  `dataDir` or a system folder, and it resolves to itself (no link). Otherwise the zone does not exist and its paths
  are `none`.
- **Write:** `write` with `create` only, reason `mod-request` only, only `requests/r-<id>.json` directly in
  `requests/` (`mkdir` of `requests/` allowed). Nothing else in that folder may be written, moved or removed.
- **Read:** the zone is a `READ_ZONES` source for `copy` into app data only, reason `mod-install`.
- The Mods write still goes through the existing `runAction` with a verified backup: the copy lands in holding first.

## Decisions already made (app, Neon)

- **Setup, once.** "Pick the Sims Helper Mods folder": the folder picker; the state is checked as above and saved.
  A one-screen guide says Tyler shares the folder with her and Google Drive for desktop shows it on her PC.
- **Send.** A text box ("Tell Tyler what you'd like the mod to do"), a live count to 2,000, **Send to Tyler**. One
  gate request writes the request file. Shown after: "Sent. Tyler will get an email." The list below shows her
  requests and their status.
- **Ready.** On app start and on the screen, read `from-tyler/*/ready.json`. A request with a valid one is `ready`:
  a card "Tyler made you a mod: <title>", his note, and **Install**. A `ready.json` that doesn't parse, names a file
  that's missing, a file not ending in `.package`/`.ts4script`, a name with a slash or `..`, or a size over 200 MB
  marks it `broken`: "This one didn't arrive properly. Tyler has been told." (nothing is installed).
- **Install.** `requests:install`: (1) copy each file from `from-tyler/<id>/files/` to
  `<holdingDir>/<entryId>/Mods/From Tyler/<title, made safe>/` (reason `mod-install`); (2) hash each copy and compare
  with `ready.json`; any mismatch removes the holding copies and refuses; (3) `runAction` with `install-mod`: `move`
  steps from holding into `Mods/From Tyler/<title>/`, backup first, journal entry, Undo in History. A target that
  exists refuses (the gate never overwrites). `hasScript` adds: "This mod needs script mods turned on in Game Options."
- **Installed** is read from the journal (a done `install-mod` entry for that request id).

## Decisions already made (relay, Opus through OpenCode)

- **Runs on `tyler-M8`** (Linux, always on) as a systemd **user** timer every 5 minutes: `relay/m8-relay.mjs`, Node
  22, no npm packages. It shells out to `rclone` (remote `simsdrive:` pointed at `Sims Helper Mods`) and `msmtp`.
- **Each run:** `rclone lsjson simsdrive:requests`; for each `r-*.json` not in `~/.local/state/sims-helper-relay/
  seen.json`: read it, validate it (format, sizes, no control characters), email Tyler (subject "Lila asked for a mod",
  body: her text, game version, packs, mod labels, and the line "Build it in T3: gfs-sim-helper"), then optionally
  POST it to the T3 webhook URL in the config, then mark it seen. A failed email leaves it unseen, so it retries.
- **Deliver:** `relay/deliver.mjs <request id> <folder with the mod files> --title ... --note ...`: refuses anything
  but `.package`/`.ts4script`, hashes each, `rclone copy`s the files, then writes `ready.json` last.
- **Config and secrets.** `~/.config/sims-helper-relay/config.json` (to address, rclone remote name, optional
  webhook URL), mode 600. The Gmail app password lives only in `~/.msmtprc` (mode 600), set up by Tyler. Nothing
  secret is in the repo, the app, her PC, a log line or an email body. The scripts never print a config value.
- `relay/README.md`: the setup steps, and `relay/systemd/` the unit and timer files.
