# Brief: PR 15, the save safety net

**Goal.** The app keeps dated copies of her saves and Tray in its own folder. She can see them, make one now, and
put any saved game back. Putting one back **adds** it as a new save in the game's load menu. It never replaces,
moves or deletes anything in `saves/` or `Tray/`.

## Decisions already made

- **What a copy holds.** Every `Slot_*.save` file in `saves/` (not the `.ver0` to `.ver4` files, not
  `scratch/`) and everything in `Tray/`. Copied to `<saveCopiesDir>/<id>/saves/` and `<id>/Tray/` with gate `copy`
  ops, reason `save-copy`, relative paths kept. Each saves file is hashed before and after; a mismatch marks the copy
  `broken`, and it is shown but cannot be put back. `copy.json` is written last; a folder without it is not listed.
- **Game must be closed.** Check `ctx.gameState()` first: `running` or `unknown` refuses. A save copied while the
  game writes it can be broken.
- **When copies are made.** By her click ("Save a copy now"); by PR 16 when the game version changed
  (`game-updated`); and before every fix or 50/50 round that changes Mods, at most once a day (`before-change`), as
  the first thing `fix:apply` does. That last hook is one call this PR adds in `src/main/fixes/handlers.ts`, the
  only line it changes outside its own paths (PR 10's file; listed in `ownership.md`). A refused copy never blocks
  the fix.
- **How many are kept.** The newest 10, plus the oldest copy of each of the last 3 game versions. Older ones are
  removed with gate `remove` ops in app data, only after a new copy is `checked`.
- **Space.** Before copying, `statfs` the data drive; refuse with `disk-full` unless free space is at least twice
  the copy's size.
- **Put back.** She picks a copy, then one save in it. The new name is the lowest unused 8-digit lower-case hex
  number above the highest slot in `saves/` (`Slot_00000009.save` exists, so `Slot_0000000a.save`). Above `Slot_0fffffff.save` answer `no-free-slot`. One gate request:
  `copy` from the copy to that name. Then read the new file back and compare its SHA-256; a mismatch says so
  plainly and leaves the file (nothing of hers was replaced). The answer names the new save: "It's in the game's
  Load menu as a new save. Your other saves are just as they were."
- **No journal entry, no Undo** for put back: it adds a file and changes nothing. History shows a line for it.
- **Screens** (Neon reviews the wording; Tyler approves): a **Save copies** screen from the main menu: the list (date,
  why, game version, how many saves, size), **Save a copy now**, and per copy **Put a save back**, which lists the
  saves in it by date and size (the game's own save names are unreadable from the file). A broken copy says "This copy
  didn't check out, so it can't be put back."

## Tests to write first

- Gate (round 7): every `saves/` and `Tray/` name except one new `Slot_<8hex>.save` refuses; an existing slot
  refuses; upper-case hex, a first digit other than `0`, 7 or 9 digits, a subfolder, `.ver0`, a source outside `saveCopiesDir` and a source through
  a link each refuse; `unknown` game state refuses; `move`/`remove`/`write` on the slot path refuse.
- Make: a fixture with 3 slots, their `.ver` files and Tray: the copy holds the 3 `.save` files and all of Tray,
  hashes match, no `.ver` file; the game running refuses and writes nothing; a hash changed mid-copy gives `broken`.
- Keep rule: 15 copies across 4 versions leave the expected set.
- Put back: the new name is one above the highest; the original folder is byte for byte unchanged except one new
  file; a broken copy refuses.
