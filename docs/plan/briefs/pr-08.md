## Decisions already made

Zones and their preconditions are in `contracts.md`, section 5. Which op may write into which zone:

| Op | mods | caches | options | app data | report |
|---|---|---|---|---|---|
| `mkdir` | yes | no | no | yes | no |
| `copy` (the `to` side) | no | no | no | yes | no |
| `move` (both sides) | yes | no | no | yes | no |
| `write` | no | no | `replace` only | yes | `create` only |
| `remove` | no | yes | no | yes | no |

An op in a zone marked "no" is refused with `outside-allowed-area`. So nothing in `Mods` is ever deleted or
overwritten: mods only move.

- **Order of checks.** (1) Every path of every op: shape, zone, links. (2) Backup, only when an op writes to mods,
  caches or options. (3) Game state, same condition, last before the first op (as built). So a `saves` path is refused as `saves-or-tray` even while
  the game runs, and a request that only writes app data never asks about the game or the backup.
- **Path shape.** Refuse (`outside-allowed-area`) any path that is not absolute, is not equal to its own
  `path.resolve`, starts with `\\?\` or `\\.\`, is a UNC path, has a part ending in a dot or a space (Windows strips
  those, so `saves.` is `saves`), or has a `:` after the drive letter (alternate data streams).
- **Links.** Resolve the deepest existing parent of each path with `realpath` and sort the result into a zone again.
  A different zone, or none: `link-escape`. Anything that resolves into `saves` or `Tray`: `saves-or-tray`.
- **Doing the ops,** in order, stopping at the first failure with `{ status: 'failed', opsDone, detail }`:
  - never overwrite (`copy`, `move`, `write` with `create`): an existing target is a failure;
  - `move`: a hard link to the new name, then remove the old name (look-then-rename where hard links are not
    supported); on a cross-drive error, copy, compare size and SHA-256, keep the file date, then remove the
    source;
  - `copy`: streamed, keeps the file date;
  - `write`: to a temp name beside the target, then rename;
  - `remove` in the caches zone accepts only the exact cache entries; in app data, anything under `dataDir`.
- Ask `deps.gameState()` once per request, immediately before the first op, and never keep the answer. A
  `gameState` or `backupStatus` that throws counts as `unknown`. "Inside OneDrive" means under one of
  `paths.oneDriveRoots`, or under a folder whose name starts with `OneDrive`.
- `detail` strings name the op and the path. They never include file contents (a `write` may carry the AI key).

## Tests to write first (they must fail before `gate.ts` has a body)

Each test builds a fixture copy in a temp folder (`generateFixture`), with a temp `dataDir` and Desktop.

- One test per refusal reason in `GateRefusal`.
- `saves` and `Tray`: plain; `SAVES`, `tray`; `Mods/../saves/x`; a link in `Mods` that points into `saves`
  (symlink, and on Windows a junction); `saves.` and `saves ` with a trailing dot or space.
- The French folder name with no-break spaces is accepted as a Sims folder; `C:\Windows` and a folder with no
  `Options.ini` are `not-a-sims-folder`.
- Game `running` and `unknown` refuse every mods, caches and options write; neither blocks an app-data write.
- Backup `none`, `stale` and `unknown` each refuse; `verified` passes.
- One test per "no" cell of the table above, and one per "yes" cell that then checks the disk.
- A refused request changes nothing: snapshot the tree before and after.
- `move` across drives (inject the cross-drive error): the target has the same hash and date, the source is gone;
  when the hash differs, the source stays and the result is `failed`.
- `failed` reports the right `opsDone`, and the ops before it really happened.
- The report zone accepts only the exact file-name pattern, on the Desktop, with `create`.
- `dataDir` inside the Sims folder, or inside OneDrive, refuses everything.
- **Lint** (`gate-lint.test.ts`): no non-test file under `src/` except `gate.ts` can reach a write. Cover named
  imports, renamed imports, whole-module imports, re-exports, `require`, dynamic `import()`, `process.binding`,
  `getBuiltinModule`, `fs-extra` and similar packages, and `child_process` outside `locate/host.ts`. `open` and
  `createReadStream` are allowed only in `src/main/fs-read.ts`.
