## Decisions already made (builder's part)

- **`assistOffer`** is `offer` only when the key is `set`, a scan exists, and either no finding is `stop` or `warn`,
  or there are logs and no `log-names-mod` finding. Otherwise `hide`.
- **`buildPreview`** makes the exact text to send, and nothing else is ever sent:
  - the game version, the symptom, and how many mod groups she has;
  - the 5 newest log reports: kind, `createdLocal`, `categoryId`, `message`, and up to 15 frames each;
  - mod group labels and file names (`RelPath`s), up to 300 groups.
  - Never saves, Tray, or any path outside `Mods`. The whole text goes through `redact`. Cut it at 40,000
    characters and end with "(list cut)".
- **`ask`** calls `keyStore.send({ model: ASSIST_MODEL, system, user: preview.text, maxTokens: 1024 })`. The `system`
  text asks for a short answer for a player who is not technical, says to call it a guess, to suggest the 50/50
  test when unsure, and never to tell her to edit or delete saves. A failed reply maps to `no-answer` with the same
  reason.
- **Handlers.** `assist:preview` builds the preview from `ctx.session.scan` and keeps the newest one in memory.
  `assist:send` takes only `previewId`: the renderer cannot change the text. An id that is not the kept one gives
  `preview-expired`. `assist:set-key` passes the key straight to `ctx.keyStore.set` and returns the status. No
  handler logs its request, and no error text from the key store is passed on.
- **The AI never runs a fix.** The answer is text. It is shown under the label "This is a guess".
- **Screens.**
  - *AskEntry* (on the check-up): "Still stuck? Ask for help", shown only on `offer`.
  - *AskScreen:* "Here is exactly what will be sent", the preview text in a scroll box, **Send** and **Cancel**;
    then the answer, or one plain message per `no-answer` reason (`declined`: "It couldn't answer this one.").
  - *KeySetupScreen* (Ctrl+Shift+K, for Tyler): a password field read through a `ref` and cleared right after
    Save, never held in React state, never logged; the status in words; **Save** and **Remove key**.
    `encryption-unavailable` says the key cannot be stored safely on this PC, and stores nothing.
- **Model.** `claude-haiku-5-5`, one constant. Check the current `@anthropic-ai/sdk` documentation before relying on
  any field name. Tyler compares Haiku with `claude-sonnet-5-5` on her real logs after G1.

## Decisions already made (Fable's part, `key-store.ts`)

- The file holds a version byte, then the bytes from `safeStorage.encryptString`. It is written through
  `deps.gate` (`reason: 'key'`, `write` with `replace`) and removed with a `remove` op.
- `setKey`: trim; refuse an empty key, one over 512 characters, or one with white space inside (status stays as it
  was). Encryption not available: return `encryption-unavailable` and write nothing.
- `keyStatus`: `set` when the file exists and decrypts; a file that will not decrypt counts as `not-set` and is
  left alone.
- `sendWithKey`: no key gives `{ status: 'failed', why: 'no-key' }`. The default transport builds the SDK client
  inside this file. Every SDK error maps to a reason and its text is dropped. A refusal from the model is `declined`.

## Tests to write first

- Builder: the text handed to `keyStore.send` equals the preview text, byte for byte. A stale `previewId` is
  `preview-expired`. `assistOffer` cases. The preview holds no user name (redacted), no `saves` or `Tray` path, and
  respects the caps. No value any handler returns contains the made-up key. With the key `not-set`, `AskEntry`
  renders nothing.
- Fable (`key-store.test.ts`), with a fake `safeStorage`, a fake gate and a fake transport: the key reaches only
  the transport; the bytes written are not the key in the clear; no thrown error, console output or return value
  contains the key; `encryption-unavailable` writes nothing; set, status, clear round trip.
- Components with `fakeApi`: the preview shows exactly the text given; Cancel sends nothing; the key field is empty
  after Save.
