## Decisions already made

- **The state is the wish; the driver makes it true.** `begin` and `answer` are pure and only say which groups
  should be `parked`. `beginRound` compares that with `fixes.disabledGroups` and calls `putBack` and `setAside` for
  the difference, then `clearCaches`. Running it twice changes nothing the second time. That is what makes a restart
  safe.
- **`begin`:** all groups are suspects, sorted script groups first, then by label. `roundsAtMost` is
  ⌈log₂ N⌉. `parked` is the first ⌈n/2⌉ suspects, `inMods` the rest. Phase `close-curseforge`, round 1.
- **`answer`:**
  - `crashed`: the cause is in `inMods`. `parked` joins `cleared`; suspects = `inMods`.
  - `worked`: the cause is in `parked`. `inMods` joins `cleared`; suspects = `parked`.
  - `not-sure`: nothing changes but `history`; the same round runs again.
  - One suspect left: phase `found`, `culprit` set, `parked` = that one group (so she can play right away).
  - Otherwise split the suspects again the same way, round + 1, phase `ready-to-test`.
- **Phases.** `close-curseforge`: waiting for her to say CurseForge is closed. `ready-to-test`: the state is saved
  but the files are not arranged yet. `awaiting-answer`: files arranged, she is testing. `found`. `stopped`.
- **`start(deps, scan)`** refuses with `out-of-date` when there is no scan or no group. It stores the scan's
  `groups` in the state, because after a restart there is no scan.
- **`beginRound`** checks `deps.host.listProcesses()`: when a name starts with `curseforge`, any letter case, it
  returns the state still in `close-curseforge` and moves nothing. A list that cannot be read does not block.
  Then it arranges the files and sets `awaiting-answer`. **G1 settles CurseForge's real process name.**
- **`giveAnswer`** saves the new state first, then calls `beginRound` unless the phase is `found`.
- **`stop`** puts every group this session set aside back, sets `stopped`, and removes the state file. **`finish`**
  with `put-back` does the same; with `keep-set-aside` it leaves the culprit set aside (it then shows as off in
  "Your mods") and puts everything else back.
- Save the state after every step. A refusal from `fixes` (game running, backup, `file-changed`) comes back as
  `refused` and the state does not advance. A half-done move comes back as `stopped-part-way`; calling `beginRound`
  again finishes it.
- **Words.** One task per screen. Round header: "Round 2 of about 6 · 16 mod groups left". The test card says what
  was done ("We set aside 16 mod groups and cleared the cache"), then: "Open The Sims 4, start a **new** test
  household (don't open your real save), and try the thing that crashed." Answers: **It still crashed**,
  **No crash, it worked!**, and a quiet "Not sure, let me test again". The result names the group and says "most
  likely". Stopping asks once: "Stop the 50/50 test and put all your mods back?"
- **`FiftyEntry`** shows "Find it with the 50/50 test" when the scan has a finding with `next: 'fifty-fifty'`, and a
  smaller link otherwise. **`ResumeBanner`** calls `fifty:get` and shows "50/50 test in progress · Round 2 of about
  6" with **Continue** and **Put everything back and stop**.

## Tests to write first

- Pure machine: for every N from 1 to 200 and every position of the bad group, scripted answers name it in at most
  ⌈log₂ N⌉ rounds; 64 groups take exactly 6.
- Script groups are set aside first. `not-sure` repeats the round. `parked`, `inMods` and `cleared` never overlap.
- Driver with a fake `Fixes` that records calls: a full session; `stop` at every phase puts every group back; a
  restart (new deps, same state file) resumes at the same round; `beginRound` twice moves nothing the second time.
- CurseForge running keeps the phase and moves nothing. A `refused` from `fixes` does not advance the round.
- Components with `fakeApi`: each phase's screen, the resume banner, both finish choices, the stop question.
