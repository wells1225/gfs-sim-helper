## 1. How the CurseForge App Manages The Sims 4 (Windows & macOS)

### Game Detection & Mod Installation Paths
- **Game executable detection** (**Sourced**: [CurseForge Sims 4 Getting Started](https://support.curseforge.com/support/solutions/articles/9000221982-the-sims-4-mods-getting-started)): CurseForge auto-scans drives or lets users manually select the executable directory:
  - Windows EA App: `C:\Program Files\EA Games\The Sims 4\Game\Bin\` (`TS4_x64.exe`)
  - Windows Steam: `C:\Program Files (x86)\Steam\steamapps\common\The Sims 4\Game\Bin\`
  - Windows Origin (legacy): `C:\Program Files (x86)\Origin Games\The Sims 4\Game\Bin\`
  - macOS: folder containing `The Sims 4.app` (e.g., `/Users/<user>/Applications/`)
- **Live user-data target folders** (**Sourced**: [CurseForge Sims 4 Manual Guide](https://support.curseforge.com/support/solutions/articles/9000221442-downloading-and-installing-the-sims-4-mods-pc-manual-guide-)): Once the game is linked, CurseForge resolves the user's standard Sims 4 user folder and writes directly into two directories:
  - **Mods (`.package`, `.ts4script`):** `C:\Users\<user>\Documents\Electronic Arts\The Sims 4\Mods\` (Windows) / `~/Documents/Electronic Arts/The Sims 4/Mods/` (macOS).
  - **Tray (Households, Lots, Rooms — `.trayitem`, `.bpi`, `.hhi`, `.rmi`, `.sgi`):** `C:\Users\<user>\Documents\Electronic Arts\The Sims 4\Tray\` (Windows) / `~/Documents/Electronic Arts/The Sims 4/Tray/` (macOS).
- **OneDrive hazard** (**Sourced**: [CurseForge Sims 4 Troubleshooting](https://support.curseforge.com/support/solutions/articles/9000222156-the-sims-4-mods-and-cc-troubleshooting)): Windows OneDrive syncing `Documents\` frequently interferes with CurseForge and Sims 4 mod visibility; CurseForge explicitly instructs users to quit/disable OneDrive when mods disappear.

### Folder & Profile Layout (No Modpack Sandboxes)
- **Single live installation, no isolated profiles** (**Sourced**: [CurseForge Sims 4 Getting Started](https://support.curseforge.com/support/solutions/articles/9000221982-the-sims-4-mods-getting-started); **Inferred** vs Minecraft profiles): Unlike Minecraft (where CurseForge isolates each modpack under its own profile directory with a `minecraftinstance.json`), Sims 4 runs against the single active `Documents/Electronic Arts/The Sims 4/{Mods,Tray}` folders.
- **Flat/app-tracked file layout** (**Sourced**: [CurseForge Sims 4 Manual Guide](https://support.curseforge.com/support/solutions/articles/9000221442-downloading-and-installing-the-sims-4-mods-pc-manual-guide-); **Inferred** from CurseForge tracking design and user reports): CurseForge extracts `.package` and `.ts4script` files directly into the tracked `Mods\` directory (and gallery files into `Tray\`) rather than organizing them into user-defined category subfolders. Moving CurseForge-installed files into custom subfolders breaks CurseForge's path tracking and 1-click updates. (Note: the Sims 4 engine itself supports `.package` files up to 5 subfolders deep and `.ts4script` files at most 1 subfolder deep.)
- **Combined `My Mods` view & "Delete All" trap** (**Sourced**: [CurseForge Sims 4 Troubleshooting](https://support.curseforge.com/support/solutions/articles/9000222156-the-sims-4-mods-and-cc-troubleshooting)): CurseForge tracks both `Mods\` and `Tray\` inside "My Mods". Selecting all (`Ctrl+A`) and clicking **Delete** inside CurseForge also deletes saved Sims and lots from the local `Tray\` library.
- **Non-CurseForge mods** (**Sourced**: [CurseForge Sims 4 Getting Started](https://support.curseforge.com/support/solutions/articles/9000221982-the-sims-4-mods-getting-started)): Running **Scan mods folder** detects manually installed mods and marks them with a folder icon, but CurseForge explicitly notes *"These mods cannot be managed through the app."*

### Local Metadata Directories & Files
- **App data roots** (**Sourced**: [CurseForge Logs Guide](https://support.curseforge.com/support/solutions/articles/9000218900-how-to-get-your-curseforge-logs), [Uninstalling CurseForge](https://support.curseforge.com/support/solutions/articles/9000240272-uninstalling-the-curseforge-app)):
  - Windows (Standalone app): `%APPDATA%\CurseForge\` (`C:\Users\<user>\AppData\Roaming\CurseForge\`) containing `agent\` and `logs\`.
  - Windows (Overwolf-bundled app): `%LOCALAPPDATA%\Overwolf\` (logs under `%LOCALAPPDATA%\Overwolf\Log`, extensions/state under Overwolf's local data) alongside agent state in `%APPDATA%\CurseForge\` when migrated.
  - macOS: `~/Library/Application Support/CurseForge/` (specifically `~/Library/Application Support/CurseForge/Agent/...`, logs in `Agent/Logs/CurseClient` and `~/Library/Logs/CurseForge`).
  - Linux (for reference): `~/.config/CurseForge/` (`agent/` and `logs/`).
- **Instance & installed-addon metadata file** (**Sourced** for Overwolf/CurseForge addon-game agent architecture; **Inferred** for exact Sims 4 `gameID: 78062` schema pending verification on a real install):
  - CurseForge's background agent maintains a JSON instance ledger at `agent/GameInstances/AddonGameInstance.json` (on Windows Standalone: `%APPDATA%\CurseForge\agent\GameInstances\AddonGameInstance.json`; on macOS: `~/Library/Application Support/CurseForge/Agent/GameInstances/AddonGameInstance.json`).
  - Documented keys in CurseForge's addon instance JSON include:
    - Top-level per game instance: `gameInstanceGuid`, `gameID` (`78062` for Sims 4), `installPath`, `installedAddons[]`.
    - Per entry in `installedAddons[]`: `addonID` (CurseForge project/mod ID), `gameID`, `installedFile` (`id`, `displayName`, `fileNameOnDisk`, `fileDate`, `releaseType`, `downloadUrl`, `modules[]`), and `installed` boolean.
  - The Chromium/Electron frontend layer also stores UI preferences and caches in Chromium `LocalStorage` (LevelDB `.ldb`/`.log`) and `databases` (SQLite) under the OS app-data folder (**Inferred** from Electron/CEF architecture).
- **Practical takeaway for our helper** (**Inferred**): Reading `AddonGameInstance.json` (read-only!) is a fast, zero-API-call way to map local files to CurseForge `addonID` + `installedFile.id` + `fileDate` when present, with MurmurHash2 fingerprinting via the CurseForge API as a fallback for manually installed or unindexed files. Never mutate CurseForge's internal agent JSON/LevelDB files while CurseForge is running.

## 2. Updates, Disabling, and Post-Patch Breakage in CurseForge

- **Updating mods** (**Sourced**: [CurseForge Sims 4 Getting Started](https://support.curseforge.com/support/solutions/articles/9000221982-the-sims-4-mods-getting-started)): When a creator publishes a newer file for a tracked CurseForge project, CurseForge shows an orange **Update** button. Users can update one mod, multi-select mods, or click **Update all**. Non-CurseForge mods cannot be updated through the app.
- **No per-mod disable toggle** (**Sourced**: absence in [CurseForge Sims 4 Getting Started](https://support.curseforge.com/support/solutions/articles/9000221982-the-sims-4-mods-getting-started) & [Troubleshooting](https://support.curseforge.com/support/solutions/articles/9000222156-the-sims-4-mods-and-cc-troubleshooting); community reports): Unlike Minecraft modpacks, the Sims 4 "My Mods" view has **no toggle to temporarily disable an individual mod**. Users must either **Delete** the mod from CurseForge (and re-download later) or disable *all* mods inside Sims 4 (`Game Options -> Other`).
- **What happens after a Sims 4 game patch**:
  1. **Sims 4 auto-disables mods** (**Sourced**: [CurseForge Sims 4 Troubleshooting](https://support.curseforge.com/support/solutions/articles/9000222156-the-sims-4-mods-and-cc-troubleshooting)): After an EA update, Sims 4 unchecks *Enable Custom Content and Mods* / *Script Mods Allowed* until the player re-enables them.
  2. **No proactive "broken" or "incompatible with installed patch" detection** (**Sourced**: [CurseForge Sims 4 Troubleshooting](https://support.curseforge.com/support/solutions/articles/9000222156-the-sims-4-mods-and-cc-troubleshooting); **Inferred** from API & app behavior): CurseForge only flags that a *newer upload exists* on CurseForge. If EA releases a breaking patch and a creator has not yet uploaded an update (or abandoned the mod), CurseForge shows no "outdated for your game version" warning and performs no crash/exception analysis. Its official troubleshooting advice for malfunctioning mods is simply: *"For help, please contact the mod's creator directly."*
  3. **Game-version tags exist on uploads, but rely on creators** (**Sourced**: [CurseForge REST API Docs](https://docs.curseforge.com/rest-api/)): Each uploaded file carries `gameVersions[]` and `sortableGameVersions[]` (e.g., Sims 4 patch strings like `1.108` / `1.129.39`). However, CurseForge's desktop app does not block launch or warn when an installed mod's tagged patch lags behind the local game version, nor does it clear `localthumbcache.package` after updates/removals (**Inferred**).
  4. **Offline-patch mismatch risk** (**Inferred**): If a player holds back a Sims 4 patch in the EA App (offline mode) and clicks **Update all** in CurseForge, CurseForge pulls newer mod builds that may require the newer game patch, breaking the older game install.

## 3. CurseForge Public API (Core / Eternal API)

- **Official documentation & console** (**Sourced**): REST docs at [docs.curseforge.com/rest-api/](https://docs.curseforge.com/rest-api/) (base URL `https://api.curseforge.com`); developer portal at [console.curseforge.com](https://console.curseforge.com/).
- **Getting a key for a small personal tool** (**Sourced**: [About the CurseForge API & Applying for a Key](https://support.curseforge.com/support/solutions/articles/9000208346-about-the-curseforge-api-and-how-to-apply-for-a-key)): Free to request via the CurseForge Console application form. Overwolf manually reviews applications on three stated criteria: (1) impact on authors' earnings, (2) impact on CurseForge servers/CDN, and (3) respect for authors' third-party distribution consent. Authenticate with header `x-api-key: <KEY>`.
- **The Sims 4 `gameId`**: **`78062`** (**Sourced** via CurseForge API game catalog references; note that `4471` occasionally seen in search snippets is Minecraft's Modpacks class ID, *not* Sims 4). Can also be verified live at runtime via `GET /v1/games`.

### Key Endpoints & Schemas (**Sourced**: [CurseForge REST API Docs](https://docs.curseforge.com/rest-api/))
| Purpose | Endpoint | Key Request / Response Fields |
|---|---|---|
| Match local files by fingerprint | `POST /v1/fingerprints/{gameId}` (e.g. `78062`) or `POST /v1/fingerprints` | Body: `{ "fingerprints": [uint32, ...] }`. Returns `FingerprintsMatchesResult`: `exactMatches[]` (`FingerprintMatch`: `id` = modId, `file`, `latestFiles[]`), `exactFingerprints[]`, `partialMatches[]`, `unmatchedFingerprints[]`. |
| Fuzzy folder+file match | `POST /v1/fingerprints/fuzzy/{gameId}` | Body: `{ "gameId": 78062, "fingerprints": [{ "foldername": "...", "fingerprints": [...] }] }`. Useful when files sit in a subfolder. |
| Batch lookup mods by ID | `POST /v1/mods` (single: `GET /v1/mods/{modId}`) | Body: `{ "modIds": [...] }`. Returns `Mod`: `name`, `slug`, `links.websiteUrl`, `authors[]`, `allowModDistribution`, `latestFiles[]`, `latestFilesIndexes[]` (`FileIndex` with `gameVersion`, `fileId`, `filename`, `releaseType`). |
| Batch lookup files / list files | `POST /v1/mods/files` or `GET /v1/mods/{modId}/files` | Returns `File`: `id`, `modId`, `displayName`, `fileName`, `fileDate`, `fileFingerprint`, `hashes[]` (`algo`: `1`=SHA1, `2`=MD5), `gameVersions[]`, `sortableGameVersions[]`, `dependencies[]`, `modules[]` (`FileModule`: `{ name, fingerprint }`), `downloadUrl`. |
| File changelog | `GET /v1/mods/{modId}/files/{fileId}/changelog` | HTML changelog string (useful for surfacing creator patch notes in plain language). |
| Official game patch versions | `GET /v1/games/{gameId}/versions` or `GET /v2/games/{gameId}/versions` + `GET /v1/games/{gameId}/version-types` | Lists valid Sims 4 version strings & release dates to compare against the local game's `GameVersion.txt`. |

- **Fingerprint algorithm** (**Sourced**: [meza/curseforge-fingerprint](https://github.com/meza/curseforge-fingerprint)): CurseForge's `fileFingerprint` is a 32-bit **MurmurHash2** (seed `1`, multiplier `1540483477`) computed over file bytes after stripping ASCII whitespace bytes `0x09` (tab), `0x0a` (LF), `0x0d` (CR), and `0x20` (space). It takes ~30 lines of pure TypeScript/Rust/Python (no GPL native addon needed).
- **Important Sims 4 archive caveat** (**Inferred** from `File` & `FileModule` schema): Many Sims 4 mods are uploaded to CurseForge as `.zip` archives that the CurseForge app extracts into multiple `.package`/`.ts4script` files on disk. The top-level `fileFingerprint` hashes the uploaded `.zip`, whereas extracted members may appear under `File.modules[]` (`name`, `fingerprint`). Whether `POST /v1/fingerprints/78062` matches loose extracted `.package`/`.ts4script` files reliably for Sims 4 must be verified with a real API key; combining local `AddonGameInstance.json` lookup + fingerprint lookup is much safer than relying on fingerprints alone.

### Rate Limits & Terms of Service That Matter (**Sourced**: [CurseForge 3rd Party API Terms & Conditions](https://support.curseforge.com/support/solutions/articles/9000207405-curseforge-3rd-party-api-terms-and-conditions))
1. **No published numeric rate limits**: Quotas are set and updated at Overwolf's sole discretion; exceeding quota can require a written (potentially paid) licensing agreement. Throttling / Cloudflare blocks frequently manifest as HTTP `403` (as well as `429`). Always use batch endpoints (`POST /v1/mods`, `POST /v1/mods/files`, `POST /v1/fingerprints/78062`).
2. **API key confidentiality**: The API key is non-transferable and **may not be disclosed to any third party**. Never commit it to Git or embed it in a publicly distributed desktop binary. For a single-user personal tool, store the user's/owner's key locally (OS keychain / local config file outside the repo).
3. **Strict "no saving or caching" clause**: Section *Restrictions and Obligations of Developer* clause `(e)` states developers shall not *"save or cache any data obtained through the API or SDK."* Keep API metadata in memory per session (re-querying in batches on scan) rather than writing a persistent disk mirror of CurseForge's catalog.
4. **No competing product & "External App" requirement**: The app must provide *"substantial functionality above and beyond"* the API and must not *"compete, directly or indirectly, with CF, CurseForge for Studios, or the Platform."*
5. **`allowModDistribution` & design implication** (**Sourced**: [REST API Docs](https://docs.curseforge.com/rest-api/), [API Key Guide](https://support.curseforge.com/support/solutions/articles/9000208346-about-the-curseforge-api-and-how-to-apply-for-a-key); **Inferred** recommendation): Authors can opt out (`allowModDistribution: false`, yielding null `downloadUrl`). Making our tool **read-only** against the CurseForge API—identifying mods, checking patch compatibility/freshness, and opening the CurseForge app/web page when an update is needed—avoids competing with CurseForge, respects author monetization, and stays well inside ToS.

### Open-Source Building Blocks Worth Knowing
- **`@s4tk/models`** ([sims4toolkit/models](https://github.com/sims4toolkit/models), **MIT**, TypeScript): Active npm library for reading/writing Sims 4 DBPF `.package` files and embedded resources (**Sourced**).
- **`s4pe` / `Sims4Tools`** ([s4ptacle/Sims4Tools](https://github.com/s4ptacle/Sims4Tools), **GPL-3.0+**, C#): Legacy open-source DBPF editor (**Sourced**).
- **`TrayTrim`** ([stixez/TrayTrim](https://github.com/stixez/TrayTrim), **MIT**, Python/PySide6) and **`sims4modorganizer`** ([subtervisor/sims4modorganizer](https://github.com/subtervisor/sims4modorganizer), **MIT**, Rust CLI): Small focused utilities showing DBPF/hash scanning patterns (**Sourced**).

### The Gap a New Tool Fills (**Inferred**)
No existing tool combines all four needs of a non-technical CurseForge Sims 4 player whose game keeps crashing:
1. **Out-of-game crash & exception triage**: Reads `lastCrash.txt`, `lastException.txt`, `lastUIException.txt`, `GameVersion.txt`, `Config.log`, and `Mods/` *even when the game crashes on launch* (where Better Exceptions and MCCC cannot run).
2. **Plain-language explanations instead of hex/tracebacks**: Translates findings into calm, actionable English (e.g., *"Script mod X was built for patch 1.108, your game is 1.129"*, *"Script mod Y is nested 2 folders deep"*, *"OneDrive is syncing your Mods folder"*, *"Two mods override the same tuning resource"*—filtering out benign CC false positives).
3. **CurseForge-aware local management**: Correlates `Mods/` files with CurseForge metadata/API without moving CurseForge-tracked files into breaking subfolders, while adding the **per-mod disable toggle** and **one-click backup/restore** that CurseForge lacks.
4. **Guided 50/50 binary-search crash isolation**: Automates the community's painful manual "50/50 method" safely—toggling halves of mods, clearing `localthumbcache.package`, tracking tested batches, and restoring everything cleanly afterward.

## 5. Recommended Desktop Tech Stack Comparison

Target requirements: Windows-first (or Windows + macOS) desktop app for a non-technical user that reads/moves local files, parses binary DBPF `.package` and ZIP `.ts4script` files, reads Sims 4 text/XML crash logs, calls HTTPS APIs, and presents a friendly UI.

| Criterion | **Electron (TypeScript + React)** | **Tauri v2 (Rust + TypeScript/React)** | **Python (PySide6 + PyInstaller / Nuitka)** |
|---|---|---|---|
| **Installer / Bundle Size** | **~100–180 MB** (bundles Chromium + Node.js) (**Sourced**) | **~10–35 MB** (uses OS WebView2 / WKWebView) (**Sourced**) | **~70–150 MB** (bundles Python + Qt libraries) (**Sourced**) |
| **Signed Installer Shipping** | **Best maturity.** `electron-builder` / Forge have turnkey Windows signing (works with [Azure Artifact Signing](https://learn.microsoft.com/en-us/azure/artifact-signing/overview), $9.99/mo Basic, US/Canada individuals eligible) & macOS notarization ([Electron Docs](https://www.electronjs.org/docs/latest/tutorial/code-signing)). Proven in Sims 4 (S4MM, Vortex). Low AV false positives. | **Good.** Built-in NSIS/WiX & `.dmg` bundlers + native [Windows signing](https://v2.tauri.app/distribute/sign/windows/) and [macOS notarization](https://v2.tauri.app/distribute/sign/macos/) hooks. Low AV false positives. Note: neither Tauri nor Electron bypasses Windows SmartScreen instantly without download reputation (**Sourced**). | **Worst for Windows end users.** PyInstaller bootloaders trigger frequent **Windows Defender / AV false positives** (**Sourced**); Nuitka reduces them but slows builds and complicates macOS `.app` recursive `.dylib` signing for notarization. |
| **Filesystem & Binary `.package` Parsing** | **Strong.** Unrestricted Node `fs/promises` + `zlib` + direct access to MIT-licensed [`@s4tk/models`](https://github.com/sims4toolkit/models) for DBPF `.package` parsing (**Sourced**). Reading headers/index tables of 5,000+ packages in worker threads takes a few seconds (**Inferred**). | **Fastest raw I/O, weaker Sims 4 ecosystem.** Rust `rayon` + `flate2` scans 10,000+ files in ~1–2s with minimal RAM, but **no maintained Sims 4 DBPF crate exists**—requires writing/maintaining a custom Rust DBPF 2.1 reader (~200–400 LOC) (**Inferred**). | **Adequate but slower.** `struct` + `zlib` + `zipfile` work well, but no maintained DBPF library (`s4py` untouched since 2014) and GIL/startup overhead slows large Mods-folder scans (**Sourced** / **Inferred**). |
| **AI Coding Agent Build & Test Ergonomics** | **Best.** Single language (TypeScript) across filesystem, DBPF parser, API client, and UI; shared types; fast `vitest` unit tests (with `maxWorkers: 2`); real desktop E2E tests via Playwright Electron; **identical Chromium rendering** on macOS dev and Windows target (**Inferred**). | **Good, higher friction.** Dual toolchain (`cargo` + Node/TS), IPC command boilerplate, slower Rust compile loops, and **different WebViews** on dev (macOS WKWebView) vs target (Windows WebView2); `tauri-driver` does not support macOS WKWebView (**Inferred**). | **Weakest for polished UI & E2E.** Easy backend tests (`pytest`), but Qt widgets require much more effort for an AI agent to craft a warm, modern, accessible consumer UI compared to React + Tailwind, and packaging is brittle (**Inferred**). |

### Recommendation: **Electron + TypeScript + React (Vite)**
**Choose Electron (with TypeScript, React, Tailwind/shadcn UI, Vitest, and Electron Forge or `electron-builder`)** (**Inferred** from the tradeoffs above):
1. **Single-user install size is a non-issue**: On a PC running The Sims 4 with many expansion packs and mods (typically 60–150+ GB), a ~130 MB installer is trivial, whereas cross-WebView rendering bugs and dual-language build overhead are real costs.
2. **Highest AI-agent velocity and testability**: One language (TypeScript) from binary `.package` header scanning to UI, with Playwright able to launch and verify the real desktop window end-to-end and `vitest` testing file operations and log parsers against fixture directories.
3. **Ready-made Sims 4 binary ecosystem**: Can leverage MIT-licensed `@s4tk/models` directly (paired with a thin fast-path DBPF 2.1 header/index reader if scanning 10k+ files needs extra speed), plus pure-TS MurmurHash2 fingerprinting (~30 lines) and standard ZIP parsing for `.ts4script` files.
